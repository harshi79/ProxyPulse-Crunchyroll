# API reference

Two surfaces:

|                    | Base URL                                              | Auth                                                                          | Purpose                                          |
| ------------------ | ----------------------------------------------------- | ----------------------------------------------------------------------------- | ------------------------------------------------ |
| **Public gateway** | the Cloudflare Worker (`https://api.your-domain.com`) | `Authorization: Bearer <reader key>` or `x-api-key`                           | read-only pool access                            |
| **Internal API**   | the Render worker origin                              | `Authorization: Bearer <INTERNAL_API_TOKEN>` or `x-proxypulse-internal-token` | what the gateway calls; also the operator's tool |

Both use the same envelope, built by `shared/src/api-envelope.ts`, so the gateway can forward bodies
without rewriting them.

## Envelope

```json
{
  "ok": true,
  "data": { "...": "endpoint specific" },
  "meta": {
    "request_id": "req_5b1c3f9a2d4e6f01",
    "timestamp": "2026-09-14T12:00:00.000Z",
    "pool_size": 1284,
    "last_update": "2026-09-14T11:58:03.000Z",
    "service": "crunchyroll",
    "cached": true,
    "stale": false
  }
}
```

- `meta.request_id` is generated by the edge (an inbound `x-request-id` matching `[A-Za-z0-9._:-]{1,64}`
  is echoed back instead), and is also returned as the `x-request-id` response header.
- `meta.pool_size` is the number of _eligible_ proxies ignoring `limit`/`offset`;
  `meta.last_update` is the newest successful check time among the returned rows.
- `meta.cached` / `meta.stale` are set by the gateway; `stale: true` means the origin was unreachable and
  the answer came from an expired cache entry.

Errors use the same shape with `ok: false`:

```json
{
  "ok": false,
  "error": { "code": "rate_limited", "message": "..." },
  "meta": { "request_id": "req_…", "timestamp": "…" }
}
```

| `code`               | HTTP | Meaning                                                           |
| -------------------- | ---- | ----------------------------------------------------------------- |
| `bad_request`        | 400  | invalid or unsupported query parameter / non-JSON body            |
| `unauthorized`       | 401  | missing or wrong key/token                                        |
| `forbidden`          | 403  | public API has no reader keys configured (production)             |
| `not_found`          | 404  | unknown endpoint                                                  |
| `method_not_allowed` | 405  | wrong method for the route (internal API)                         |
| `conflict`           | 409  | a refresh cycle is already running                                |
| `payload_too_large`  | 413  | request body above `MAX_REQUEST_BYTES`                            |
| `rate_limited`       | 429  | per-key/per-IP window exceeded (`Retry-After` set)                |
| `timeout`            | 504  | the pool origin did not answer in time                            |
| `unavailable`        | 503  | no healthy proxies match the filter, or the origin is unreachable |
| `upstream_error`     | 502  | the origin returned a non-JSON/malformed/error response           |
| `internal_error`     | 500  | unexpected failure (details stay in the logs, never in the body)  |

Common response headers: `x-request-id`, `x-proxypulse-endpoint`, `x-proxypulse-cached`,
`x-proxypulse-stale`, `cache-control`, `age` (on cache hits), `ratelimit-limit`, `ratelimit-remaining`,
`ratelimit-reset`, `retry-after` (on 429), and permissive CORS for `GET`
(`access-control-allow-origin: *`, `access-control-allow-headers: authorization, x-api-key, x-request-id`).

## Public endpoints

### `GET /pool`

Paged view of the healthy pool. Cached at the edge for 30 s.

| Query            | Default    | Range                            | Notes                                                                                                                                         |
| ---------------- | ---------- | -------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `limit`          | 50         | 1–500                            | values above 500 are clamped and reported in `data.warnings`                                                                                  |
| `offset`         | 0          | 0–100 000                        | page offset                                                                                                                                   |
| `protocol`       | –          | `http` `https` `socks4` `socks5` | anything else → 400                                                                                                                           |
| `min_score`      | 0          | 0–100                            | pool floor is additionally bounded by `POOL_MIN_SCORE`                                                                                        |
| `max_latency_ms` | –          | 0–600 000                        | only rows with a measured latency                                                                                                             |
| `country`        | –          | 2-letter ISO                     | e.g. `DE`; other formats → 400                                                                                                                |
| `service`        | `required` | `required` `preferred` `off`     | `required` = only proxies that passed the service check; `preferred` = verified first, unverified allowed; `off` = ignore the service verdict |

```json
{
  "ok": true,
  "data": {
    "service": "crunchyroll",
    "pool_size": 1284,
    "count": 2,
    "limit": 50,
    "offset": 0,
    "returned_at": "2026-09-14T12:00:00.000Z",
    "next_refresh_in_seconds": 412,
    "filters": {
      "protocol": "socks5",
      "min_score": 70,
      "max_latency_ms": null,
      "country": null,
      "service": "required"
    },
    "proxies": [
      {
        "id": 4812,
        "host": "203.0.113.10",
        "port": 1080,
        "protocol": "socks5",
        "source": "proxifly-socks5",
        "score": 91.5,
        "latency_ms": 118,
        "country": "US",
        "anonymity": "anonymous",
        "last_passed": "2026-09-14T11:58:03.000Z"
      }
    ]
  },
  "meta": { "pool_size": 1284, "…": "…" }
}
```

Proxy objects are exactly the ten fields above — ordered by `score DESC`, then latency, then id. There is
never a `username`, `password`, `dedupe_key`, internal status or error code in a public payload.

### `GET /random`

One score-weighted proxy. Not cached (so repeated calls rotate), same filters as `/pool`. The worker
samples the top 200 matching rows and picks randomly with probability proportional to `score`, which
keeps the best members likely without hammering a single address. Empty pool → `503 unavailable`.

```json
{
  "ok": true,
  "data": {
    "service": "crunchyroll",
    "pool_size": 1284,
    "proxy": {
      "id": 991,
      "host": "…",
      "port": 8080,
      "protocol": "http",
      "score": 88.5,
      "latency_ms": 96,
      "country": "NL",
      "anonymity": "unknown",
      "source": "…",
      "last_passed": "…"
    }
  },
  "meta": { "…": "…" }
}
```

### `GET /tpool`

The compact "latest test cycle" summary the spec asks for — `{service, valid, last_check, next_check}`
plus the cycle detail. Cached for 20 s.

```json
{
  "ok": true,
  "data": {
    "service": "crunchyroll",
    "valid": 611,
    "last_check": "2026-09-14T11:58:03.000Z",
    "next_check": "2026-09-14T12:15:00.000Z",
    "cycle": {
      "cycle_id": "cyc_20260914T114500Z_9f2c",
      "status": "completed",
      "started_at": "…",
      "finished_at": "…",
      "duration_ms": 84120,
      "candidates_discovered": 5210,
      "candidates_checked": 2000,
      "candidates_passed": 268,
      "candidates_failed": 1732,
      "service_checked": 250,
      "service_passed": 181,
      "pool_size": 1284
    }
  },
  "meta": { "pool_size": 1284, "last_update": "2026-09-14T11:58:03.000Z", "…": "…" }
}
```

`valid` counts proxies whose **service** verdict is currently `passed` and still fresh (within
`POOL_TTL_MINUTES`); `next_check` is the scheduler's next run (persisted in `meta`, so it survives a
restart).

### `GET /health`

Proxied to the origin's `/health` (never cached, no key required): `{ok, service, version,
environment, uptime_ms, database:{ok,latency_ms}, scheduler:{…}}`. `503` when the database is
unreachable.

### `GET /` and `GET /healthz`

Edge-only (never proxied, no key required). `/` lists the endpoints and the configured rate limit and
cache TTLs; `/healthz` reports the gateway itself — including the reason when the Worker's bindings are
misconfigured, which makes a bad deploy visible without reading the dashboard.

## Caching and rate limiting (edge)

- Cacheable: `/pool` 30 s, `/stats` 15 s, `/tpool` 20 s. Never cached: `/random`, `/health`,
  `/healthz`. Cache keys are `pathname + sorted query` with `bypass_cache` removed; keys never include
  credentials, and every response is re-signed with a fresh `request_id`/`timestamp` so a cache hit
  cannot leak another caller's id.
- On an origin failure the gateway serves the expired entry with `meta.stale = true` (and `age`), so a
  running refresh cycle or a brief Turso hiccup does not take the API down.
- `?bypass_cache=1` forces an origin fetch — accepted only outside `ENVIRONMENT=production`.
- Rate limit: fixed window per API key (falling back to client IP for unauthenticated probes),
  `RATE_LIMIT_MAX`/`RATE_LIMIT_WINDOW_SECONDS` (default 120/60). Counters live in the `RATE_LIMIT_KV`
  namespace when configured; without KV they are per-isolate, which is a soft limit by design — the
  limiter always fails open rather than returning 500s.

## Internal API (worker origin)

All routes require the internal token. `pool_size`/`last_update` are also surfaced in `meta` here.

| Route                           | Description                                                                                                                                                                                                                          |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `GET /health`, `GET /ready`     | unauthenticated liveness/readiness for Render's health check                                                                                                                                                                         |
| `GET /internal/pool`            | same filters as the public `/pool`                                                                                                                                                                                                   |
| `GET /internal/random`          | same as the public `/random`                                                                                                                                                                                                         |
| `GET /internal/stats`           | same as the public `/stats` (`?errors=1` supported)                                                                                                                                                                                  |
| `GET /internal/tpool`           | same as the public `/tpool`                                                                                                                                                                                                          |
| `GET /internal/cycles?limit=20` | recent cycle history (max 100)                                                                                                                                                                                                       |
| `GET /internal/cycle/current`   | the running cycle row plus scheduler status                                                                                                                                                                                          |
| `POST /internal/cycle/run`      | trigger a cycle now → `202 {started:true, cycle_id}`; `409` if one is running. `?wait=1` blocks until it finishes and answers with the outcome                                                                                       |
| `POST /internal/jobs`           | enqueue one job: `{"type":"VALIDATE","proxy_id":123,"reason":"manual"}` → `202 {job_id}`; `400` on an unknown type or a missing `proxy_id`. Types: `DISCOVER`, `VALIDATE`, `SERVICE_CHECK`, `RECHECK`, `POOL_UPDATE`, `STATS_UPDATE` |
| `GET /internal/metrics`         | Prometheus text: `proxypulse_up`, `proxypulse_pool_size`, `proxypulse_proxies{status=…}`, `proxypulse_service_passed{service=…}`, `proxypulse_avg_latency_ms`, `proxypulse_cycles_total{result=…}`, `proxypulse_uptime_ms`           |

`POST /internal/cycle/run` is also what the gateway's optional Cron Trigger calls
(`CYCLE_TRIGGER_MODE=trigger`); in the default `keepalive` mode the trigger only GETs `/health`, which is
what keeps a sleeping free-tier origin awake without changing the worker's own cadence.

The internal API additionally enforces `MAX_REQUEST_BYTES` on bodies (413), a per-client rate limit
(240/min), and 405 with an `Allow` header for the wrong method. It returns the same envelope as the
public API, so `curl` against the origin behaves identically to the gateway.

```bash
TOKEN=$(grep '^INTERNAL_API_TOKEN=' .env | cut -d= -f2)
curl -H "authorization: Bearer $TOKEN" 'http://127.0.0.1:8080/internal/pool?limit=5&service=off'
curl -X POST -H "authorization: Bearer $TOKEN" 'http://127.0.0.1:8080/internal/cycle/run?wait=1'
curl -H "authorization: Bearer $TOKEN" http://127.0.0.1:8080/internal/metrics
```

## Versioning and stability

The envelope, the ten public proxy fields, the filter names and the error codes above are the contract.
Additive changes are non-breaking; anything that would remove or rename one of them is a major version
bump. The internal API is not covered by that promise, but `docs/DEPLOYMENT.md` pairs the two deploys
from the same commit, which keeps them in step.
